# lambada 3.0.0

## nginx does the web side now; lambada is just the MTA

nginx serves the scans folder over WebDAV, so the Go web server
(`lambada-web`) and its custom `files.json` protocol are gone. What's left
is one small service, `lambada`, the SMTP server that receives scans; its Go
code moved from `cmd/lambada-mta` to the repo root. The old web server is
at the `lambada-web-final` tag. (#19, #20, #21)

## A Finder-style page, and uploads

Browsing to `http://<pi>/` shows every file with its name, size and age,
with a file-type icon and a trash can, in one Finder-style list (two lines
per file on a phone). Any WebDAV client works too: Finder (Go → Connect to
Server, connect as Guest), zouk, huck.

Files can now be uploaded, up to 25 MB each, into the top-level folder: drag
them onto the page, use its "upload files" button, or drag them into Finder.
(#22)

The page is plain TypeScript, built into one minified `public/main.js`
(about 7 KB gzipped, icons included) that's committed, so the Pi still needs
no npm. nginx sends the page's files with `Cache-Control: no-cache`, so an
update shows up on the next reload.

## Cleanup only deletes scans

When a scan arrives, lambada deletes scans older than 24 hours, as before,
but now only files named like a scan (ten digits plus `.pdf`). Uploads and
anything else stay until someone deletes them. An upload that has a scan's
name (usually a downloaded scan put back) counts as a scan.

## Upgrading from 2.x

`make install` builds and installs `lambada` and the page. Then replace the
two old services with `service/lambada.service` and install
`service/lambada.nginx.conf` as nginx's site; `docs/DEVELOPMENT.md` has the
exact commands ("Upgrading from lambada-mta and lambada-web"). zouk and huck
need their WebDAV releases, since `files.json` is gone.
